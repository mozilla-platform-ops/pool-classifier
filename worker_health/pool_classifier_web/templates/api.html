API
OverviewPatternsAPIAbout

Versioned, read-only JSON endpoints for pool discovery, health summaries, utilization, and observed task-run start lag. Substitute a pool's provisioner and worker type in the paths below.

Endpoints

MethodEndpointPurpose
GET/api/v1Returns the v1 discovery document and endpoint list.
GET/api/v1/poolsReturns configured pools, including disabled pools and availability modes.
GET/api/v1/pools/{provisioner}/{worker_type}/summaryReturns worker, task, freshness, and collection-coverage health metrics.
GET/api/v1/pools/{provisioner}/{worker_type}/utilizationReturns bucketed, duration-weighted utilization for a requested time range.
GET/api/v1/pools/{provisioner}/{worker_type}/utilization/summaryReturns the standard trailing 1h, 24h, 7d, and 30d utilization windows.
GET/api/v1/pools/{provisioner}/{worker_type}/observed-start-lagReturns observed scheduled-to-start lag for terminal runs; it excludes runs that never started.
GET/api/v1/pools/{provisioner}/{worker_type}/observed-start-lag/visualizationReturns the same observed-start-lag data shaped for charting, with a configurable min_samples.

Usage

The bucketed endpoint requires ISO 8601 start and end parameters plus bucket_seconds. Ranges are limited to 90 days and 2,000 buckets. Responses include coverage and availability-mode metadata.

The observed-start-lag endpoint requires ISO 8601 start and end, and accepts slo_seconds. It is not a queue-total or pool-health metric: runs that never started are not visible to this collector.
